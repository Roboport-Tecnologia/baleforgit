# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Start here

- **`docs/ARCHITECTURE.md`** — read this before making non-trivial changes. It covers the three pluggable traits (`BlobStore`, `MetadataStore`, `RepoAuthz`), upload/download/global-dedup flows, the wire surface, storage layout, auth flow, the native `git-bale` filter, the OpenTelemetry observability story (gated on `OTEL_EXPORTER_OTLP_ENDPOINT`), and a "Tricky bits" section calling out the parts of the Bale protocol that are easy to get wrong (hex encoding, `url_range` end-inclusivity, signed-URL Range matching, idempotency, shard magic tag).
- **`docs/BALE_FORGE_PROTOCOL.md`** — the contract a git forge has to implement to support `git-bale`: an HTTPS `/info/bale/authenticate` endpoint, an SSH `git-bale-authenticate` command, and a `POST /check_access` callback consumed by `bale-server-authz-http`. Read before touching the `git-bale` auth resolver or `HttpAuthz`.
- **Milestones (M1–M8, M11, M12, M13)** are all done. M1–M6 are the server itself; M7 drives real `git-xet`; M8 swaps in alternate trait impls; M11 is the native `git-bale` filter; M12 is the per-repo scope check on reconstruction; M13 is per-owner + per-repo storage accounting + quotas + the `/v1/usage/{owner}`, `/v1/usage/repo/{owner}/{repo}`, and `/v1/quotas/{owner}` endpoints. (M9/M10 covered an LFS-bridge adapter that has been removed.) Each has a `crates/bale-server-tests/tests/m<N>_*.rs` integration test.
- **`crates/git-bale/`** — native Git filter (`filter.bale.process`). Pretty-printed JSON pointer with stable key order (`hash`, `file_size`, `sha256`), shared chunk cache (`~/.cache/bale/chunks` by default), per-repo manifest cache (`.git/bale/manifests/`), and a per-repo **pointer cache** (`.git/bale/clean-cache/<blake3>`) that short-circuits `clean` when the same input bytes have been cleaned before — `git status` / `git diff` on a modified bale file would otherwise re-run full CDC + xorb + shard work on every command. **Clean is offline: `git add` chunks the file via `TranslatorConfig::local_config` and writes xorbs/shards to `.git/bale/staging/` instead of POSTing to the server.** `git-bale push-pending` drains the staging dir (POSTs xorbs to `/v1/xorbs/default/{hash}` and shards to `/shards` — shards have the lookup tables + footer stripped before upload, mirroring xet-data's `read_shard_to_bytes_remove_footer`), and the pre-push hook installed by `git-bale install --local` runs it before `git push`. Smudge order: hot path (manifest + chunk cache) → lukewarm path (reconstruct from `.git/bale/staging/` if not yet pushed) → cold path (`/v1/reconstructions/`). Auto-resolves `server_url` + token from `origin` via the forge protocol (HTTPS Basic via `git credential fill`, or SSH `git-bale-authenticate`); falls back to `bale.serverUrl` + `bale.token` from local git config when both are set. Drives the m11 integration test. Depends on `xet-data`, `xet-client`, `xet-core-structures`, `xet-runtime` from crates.io, pinned to `=1.5.2`. Also uses `gix` for pure-Rust git ops: rev-parse, tree diff, ODB blob reads, `gix::discover` + config snapshot in `config.rs` (replacing `git rev-parse --git-dir` + `git config --get-regexp`), `find_remote("origin")` in `remote.rs` (replacing `git remote get-url origin`), and `git_dir().join("hooks")` (with `core.hooksPath` honored from the snapshot) in `install.rs` (replacing `git rev-parse --git-path`). Things still shelling out: `git credential fill` and SSH in `resolver.rs` (forge auth — no library equivalent), and `git config --local/--global/--system` writes in `install.rs` (one-time setup, gix's typed-key write API is more complex than the subprocess for arbitrary user keys). The `xet-core/` sibling clone is present only as a source reference for Claude — it's not in the build graph, and the root `Cargo.toml` `exclude`s it so cargo doesn't try to descend into its workspace.
- **`tests/e2e/`** — out-of-band full end-to-end harness (`tests/e2e/run.py`) that bundles `baleforgit-server` + `openssh-server` in one podman container and drives the release `git-bale` binary through stage/unstage/stash/pop/commit/push/clone over real SSH. Includes a 35 MB binary with two slight modifications so chunk-level dedup is verifiable against on-disk numbers AND the `/v1/usage/...` API, plus adversarial cases (wrong token, tampered xorb on disk, quota exceeded). A companion `tests/e2e/run_s3.py` (helpers in `tests/e2e/s3lib.py`) brings up a MinIO sidecar via `podman run` and runs four S3-targeted phases — happy-path push/clone, chunk-level dedup against MinIO object counts, server killed mid-PUT to S3, and a NEW server↔S3 connection drop via a host-side TcpProxy + `host.containers.internal`. Not run by `cargo test --workspace`. Read [`tests/e2e/README.md`](tests/e2e/README.md) — especially the **Design** section — before changing the harness, the bundled `Dockerfile`/`entrypoint.sh`, or any wire bit the test depends on (the resolver's scp-style URL parser, the JSON pointer shape, the `BALE_GRANTS` env format, the `/v1/usage` response shape, the `clean-cache` schema). Pure stdlib Python; runs on Linux/macOS/Windows hosts without pip.
- **`crates/git-bale/src/mount/`** — two read-only FUSE mounts that share infrastructure: `git-bale mount-diff <revA> <revB>` (both sides of a diff, names labelled `name__<label>.ext`) and `git-bale mount <rev>` (single revision, original names). `mount-diff` populates its inode tree up front from the diff result; `mount <rev>` is *lazy* — directories carry an unresolved gix tree OID and read their children only when FUSE first looks inside, so mounting a 100k-file repo doesn't walk 100k tree objects at startup. Plain blobs stream from the ODB (cap 16 MiB), Bale pointers reconstruct via cache-first then network-fallback (same hot/cold path as the smudge filter). libfuse is dlopened at runtime via `libloading` — `libfuse.so.2` on Linux, `libfuse-t.dylib` on macOS (no kext via fuse-t); the binding is libfuse 2.x because fuse-t advertises 2.9.9 and binding to libfuse 3 silently mis-positions every op slot after `readlink`. The workspace builds on machines without libfuse; missing libfuse triggers a friendly install-hint exit before any other work. Backend trait under `mount/backend/` keeps libfuse swappable for WinFsp / etc. later. See `docs/ARCHITECTURE.md` § "`git-bale mount-diff` and `git-bale mount`" for tricky bits (path-based callbacks, OnceLock active-VFS, never-reconstruct `getattr`, lazy-dir population, per-open tempfile handles).

## Common commands

```bash
cargo build --workspace
cargo test --workspace
cargo test -p bale-server-tests --test m4_download_roundtrip          # one integration test file
cargo test -p bale-server-tests --test m5_auth_flow -- forged_jwt     # one named test
cargo fmt --all
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
```

The pre-commit hook (`.pre-commit-config.yaml`) runs `cargo fmt --check` and the clippy command above with `-D warnings`. **Both must pass before declaring a code task done** — run them yourself, don't wait for the user's commit to find out.

Running the binary needs two hex secrets and either `BALE_GRANTS` (static dev authz) or `BALE_AUTHZ_HTTP_URL` (delegate to an upstream `/check_access`); see `README.md` "Quick start".

## Test conventions

- Integration tests live in `crates/bale-server-tests/tests/m*.rs`, one file per milestone. Most drive the axum router via `tower::ServiceExt::oneshot` — no real HTTP server.
- `m7_git_xet.rs` is the exception: it binds the router to an ephemeral TCP port via `tokio::net::TcpListener` + `axum::serve` and spawns the real `git-xet transfer` subprocess. It **skips with an eprintln** when `git-xet` isn't on PATH, so don't be surprised if it's a no-op on a clean machine.
- `m8_pluggability.rs` drives the same `tower::oneshot` flow as M3–M6 but wired to the alternate trait impls (`MemBlobStore` + `HttpAuthz`). The HTTP-backed `RepoAuthz` makes real outbound HTTP calls to an in-process mock upstream via `reqwest`, so this test does need a working network stack (loopback only).
- `m11_native_filter.rs` builds `crates/git-bale` via `cargo build -p git-bale` at test setup and invokes it via the absolute path written into `filter.bale.process` in the local git config. **Skips silently** if `git` or `cargo` isn't on PATH, *or* if the build itself fails (defensive — keeps a transient cargo failure from masquerading as a real product bug). The test drives `git add` (which Git fans out to a long-running `git-bale filter-process` subprocess), commits, wipes the worktree file, the shared chunk cache, *and* `.git/bale/manifests/` and does `git checkout --` to force a cold smudge that must round-trip to the server; then repeats the wipe-and-smudge without touching the manifests/chunks directories to assert the hot path makes zero `/v1/reconstructions/*` calls. Asserts the staged blob is a JSON pointer (not the original bytes).
- `m12_repo_scope.rs` covers the reconstruction scope check end-to-end: same content registered in two repos, cross-repo dedup at the chunk layer, and the 404-vs-403 distinction on miss. Drives the same `tower::oneshot` flow as the other M3–M6 tests.
- `m13_quotas_and_usage.rs` covers per-owner accounting + quotas: same-owner cross-repo dedup makes `raw > stored` (the savings story), per-owner accounting is independent (no cross-owner attribution), the xorb-upload quota check rejects new bytes that would exceed it, the shard-upload re-check catches the cross-owner-dedup case (alice's xorb attributed to bob when bob references it), the admin endpoint requires `BALE_ADMIN_TOKEN_HEX` and returns 404 when unconfigured, and `/v1/usage/{owner}` forbids cross-owner viewing.
- `crates/bale-server-storage-s3/tests/minio.rs` drives `S3BlobStore` end-to-end against a MinIO container launched via `podman run --rm -d`. Marked `#[ignore]` so `cargo test --workspace` doesn't pull a ~100 MiB image — invoke with `cargo test -p bale-server-storage-s3 --test minio -- --ignored` (also how CI should run it). Probes `podman info` (not just `podman --version`) so it skips when the macOS `podman machine` VM is stopped instead of hanging on `podman run`. Covers idempotent puts, NotFound on missing xorbs, presigned-GET fetched over the wire, and verifies S3 rejects a presigned URL replayed with a different `Range:` header (the property the reconstruction handler relies on).
- SQLite tests use `:memory:` via `SqliteMetadataStore::open_path(":memory:")`.
- Filesystem tests use `tempfile::tempdir().keep()`. Do NOT use `into_path` — it's deprecated and clippy will reject it under `-D warnings`.

## Engineering guidelines

- **Comments earn their place.** Prefer self-explanatory code. Only add a comment for the non-obvious *why* — a hidden constraint, a workaround, a load-bearing invariant, an interaction with the wire protocol. No paragraphs, no docstrings that restate the function signature, no "this function does X" headers. Recent commits ("Trim comments a bit", "Optimize comments") deliberately deleted a lot of noise; don't reintroduce it.
- **Trim comments on every code change.** After writing or editing code, do a dedicated pass over the diff to simplify, trim, or remove comments and docstrings — *before* reporting the task done, not as a follow-up the user has to request. Drop function-shape docstrings, "what" comments that restate code, and section banners inside function bodies. Keep only *why* comments, and tighten the survivors (one line, name the actual failure mode in concrete terms).
- **Update the docs in the same change.** Any change that touches a trait signature, a wire endpoint, an env var, the storage schema, the auth flow, or a "Tricky bits" item must update `docs/ARCHITECTURE.md`, `docs/BALE_FORGE_PROTOCOL.md`, `README.md`, and/or this file as appropriate. Stale docs are worse than no docs.
- **Treat user data as load-bearing.** This system is a primary store for large binary artifacts — corruption is not recoverable from git history. Be paranoid about:
  - **Consistency** — writes that span the blob store and the metadata store must remain correct under partial failure. Prefer content-addressed idempotency (re-upload returns success) over locks. When persisting on the filesystem, write to `tmp/` then `rename(2)`. Never leave a half-written xorb or shard visible.
  - **Concurrency** — handlers are `async` and the router is shared across requests. Don't assume serialised access. Verify that two concurrent uploads of the same content, two concurrent reconstructions of the same file, or an upload racing a dedup query all converge to a consistent state.
  - **Security** — the M12 scope check is load-bearing; don't relax it (404, not 403, on cross-repo probes). Signed transfer URLs must enforce the `Range` match and use constant-time signature compare. Never log JWTs, hub bearers, or signing keys. New endpoints default to *inside* the auth middleware; opting out is a deliberate decision that needs justification in the code.
- **Avoid crashes.** No `unwrap` / `expect` / `panic!` / `unreachable!` on inputs that can come from the network, the filesystem, env vars, or another process. Use `?` with a typed error (`CoreError`, `ApiError`, `anyhow::Error` at binary edges). `expect` is only acceptable for invariants the compiler can't prove but the surrounding code does — leave a one-line comment saying why it can't fail. A server crash kills every in-flight request; a returned error doesn't.

## Don't "fix" these without being asked

`Range:`-on-request support on `/v1/reconstructions/*` is intentionally absent — the prototype always returns the full file's terms. The native `git-bale` smudge handler passes `0..file_size` (not `FileRange::full()`) when calling `xet-data` to avoid tripping the prefetcher; don't "simplify" that range cap without reading the comment in `crates/git-bale/src/filter_process.rs`. The same cap is mirrored in `crates/git-bale/src/mount/reader.rs` for the same reason.

libfuse in `mount/backend/libfuse.rs` is loaded with `libloading` at runtime, not linked at build time. Don't switch it to `extern "C"` linkage or a `-sys` crate — that would force every developer to install libfuse just to build the workspace, even if they never run `mount-diff`.
